# Лабораторні роботи №6–7
**Тема:** Розробка фронтенду програмного продукту.  
**Проєкт:** Вебсистема трасування вимог до тестів.

## Мета
Розробити прототип адаптивного вебінтерфейсу для керування вимогами, тест-кейсами та зв’язками трасування; забезпечити взаємодію з тестовим REST API.

## Користувацькі сценарії
1. Аналітик відкриває перелік вимог, шукає потрібну, додає або редагує вимогу.
2. Тестувальник переглядає тест-кейси та прив’язує тест до вимоги.
3. Менеджер відкриває дашборд і перевіряє відсоток покриття вимог тестами.
4. Користувач працює з інтерфейсом на комп’ютері або смартфоні.

## Карта навігації
```text
TraceFlow
├── Огляд (Dashboard)
├── Вимоги
│   ├── Список, пошук, фільтр
│   ├── Модальне вікно додавання
│   └── Модальне вікно редагування
├── Тест-кейси (перегляд)
└── Матриця трасування
    ├── Перелік зв'язків
    └── Форма створення зв'язку
```

## Схема декомпозиції інтерфейсу
```text
App
├── Sidebar (навігація)
├── Header (заголовок / меню)
├── Dashboard (метрики + останні вимоги)
├── Requirements
│   ├── RequirementCard × N
│   └── RequirementModal (додавання/редагування)
├── Tests
└── Traceability (матриця + форма прив'язки)
```

## Макети й адаптивність
Широкий екран: фіксована ліва панель, сітка 4 KPI, картки вимог у 3 колонки. На ширині до 760px: прихована ліва панель із кнопкою меню, KPI у 2 колонки, картки у 1 колонку, форми вертикально. Макети та скриншоти додаються після запуску проєкту у браузері.

## Зберігання стану і запити
- `App.jsx`: `useState` тримає `requirements`, `tests`, `links`, `loading`, `error` та стан модального вікна.
- `useEffect`: паралельно отримує `/api/requirements`, `/api/testCases` та `/api/traceLinks`.
- `RequirementModal.jsx`: локальний стан форми, перевірка назви, виклик `onSave`.
- `api.js`: спільний метод `request` та REST CRUD через `fetch` (`GET`, `POST`, `PATCH`, `DELETE`).
- Після успішних запитів локальний стан змінюється без перезавантаження сторінки.

## Аналіз usability
Застосовано видимі назви дій, одну основну кнопку дії на екрані, пошук і фільтри, статусні індикатори, підтвердження видалення, підказки для форм, повідомлення про помилки, адаптивне меню. Передбачено візуальну ієрархію та контрастні кнопки. Автоматизовані UX-тести і перевірка доступності залишаються подальшою роботою.

## Обґрунтування
React і компонентна структура зменшують дублювання UI; Vite забезпечує швидке середовище розробки; звичайний CSS з Grid/Flexbox спрощує адаптацію; json-server дозволяє працювати з асинхронним CRUD до появи Django REST API.

## Висновок
Підготовлено адаптивний прототип вебсистеми трасування вимог до тестів з основною навігацією, списком вимог, формою додавання/редагування, каталогом тестів, матрицею трасування та асинхронними CRUD-запитами до mock REST API. Для повного підтвердження виконання роботи потрібно локально запустити проєкт та зробити скриншоти desktop/mobile.
